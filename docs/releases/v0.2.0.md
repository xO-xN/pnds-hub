# PNDS HUB v0.2.0

Adds optional network-location metadata for Telematic Network Diagnostics v0.8.0 while preserving token authentication, room isolation, echo and ordinary opaque relay behavior. No audio is carried.

- `welcome.network` and `network` updates provide the observed public exit IP, approximate node position and operator-configured HUB position.
- Nodes may correct their own coordinates for the connection; `null` restores the automatic estimate. Telematic stats receive HUB-authoritative network metadata.
- IP estimates use HTTPS requests from the HUB to ipapi.is. The key stays server-side; queries have a bounded cache, concurrency, timeout and daily request budget. Private and special-use addresses are not queried.
- Exact trusted-proxy addresses must be configured before using forwarded client IPs. Missing deployment coordinates leave the HUB location unknown.

## Operator upgrade

For an existing installation using this repository's `/opt/pnds-hub` layout, run between performances:

```sh
sudo /opt/pnds-hub/update.sh v0.2.0
curl --fail http://127.0.0.1:4000/
# PNDS telematic hub v0.2.0
```

Keep the existing `hub.env` and token. Configure `HUB_TRUST_PROXY` for the actual reverse proxy, and optionally `HUB_LOCATION_LABEL`, `HUB_LOCATION_LATITUDE`, `HUB_LOCATION_LONGITUDE` and `HUB_GEO_API_KEY` as described in the README, then restart the service. Do not put the API key or token in client URLs. An update restarts the HUB; existing clients reconnect automatically. The previous tag remains available for rollback with the same update command.

Publishing this source release does not update any third-party server. Its operator must perform the deployment. Node.js 18 or later is required; the new implementation adds no production dependency.
